flex-sankey

A modular Sankey diagram layout library for JavaScript. Crossing reduction by simulated annealing, node placement by a spring relaxation, and a ribbon geometry that keeps parallel links from overlapping.

Open the demos GitHub repository Install

Unlike most Sankey libraries, flex-sankey does not hide the layout behind a single entry point. Each stage of the pipeline is a separate function that can be tuned, inspected, or replaced between steps — which is what makes it possible to do things like reuse one diagram's node ordering to seed another's, or merge a horizontal and a vertical layout into one hybrid figure. The package has no runtime dependencies and runs unchanged in Node.js and in the browser.

Three pieces do the substantive work:

  • Crossing reduction by local search. Ordering nodes to minimise link crossings is NP-complete, so stage 3 sweeps each layer into the order suggested by its neighbour — by median or barycentre — then refines with pairwise swaps accepted under a simulated-annealing rule, so the search can climb out of local minima instead of stalling in them.
  • Node placement by physical relaxation. Stage 4 treats nodes as masses sliding along their layer under three kinds of spring — edge springs pulling connected nodes into alignment, node springs holding a minimum separation, margin springs drawing the extremes toward the boundary — each with its own stiffness, with hard constraints applied after every step.
  • Overlap-free ribbon geometry. Each link is bounded by two independent cubic Béziers whose control points derive from a reference line joining the node centres, which makes adjacent parallel ribbons share their boundary curve exactly.

There is a paper. An Original Software Publication describing the library — its architecture, the ribbon construction, and a reproducible benchmark against the two most widely used D3 implementations — is being submitted to SoftwareX. Every figure and number in it is generated by the code in this repository; see benchmarks/.

Why the ribbon geometry differs

A Sankey link is a ribbon of constant breadth. The usual approach takes a single cubic Bézier centre line and dilates it. But the offset curve of a cubic Bézier is not itself a Bézier, which causes two visible problems:

  • ribbons distort badly when their endpoints are close along the flow direction but far apart across it;
  • parallel ribbons between the same pair of nodes overlap one another.

flex-sankey builds each ribbon from two independent cubic Béziers, one per side, whose interior control points are derived from a reference line joining the two nodes. Anchoring that reference line at the node centres makes adjacent parallel ribbons share their boundary curve exactly — so they tile the node's extent with neither gap nor overlap. That property is asserted as an executable test rather than left as a claim.

The ribbon geometry demo measures the difference live. For a simple parallel bundle the arc-based construction does just as well; the three separate in the hard case, where nodes sit close together along the flow but far apart across it. There the improved construction still measures 0 % overlap, while arcs reach about 12 % and a dilated Bézier over 60 %.

Install

Not published to a registry. Clone it, or add it as a git dependency:

npm install github:esperanc/flex-sankey

Usage

The convenience entry point runs every stage and returns SVG markup:

import { flexSankeySVG } from "flex-sankey";

const svg = flexSankeySVG({ links }, {
  width: 800, height: 500,
  pathColor: "source-target"
});

Calling the stages individually is what the architecture is for. This reuses one dataset's node ordering to seed another's, which converges markedly faster than starting afresh and keeps the two diagrams visually comparable: 

const a = sankeyOrderNodes(
  sankeyAddDummies(sankeyLayers({ links: y2023 })),
  { nsteps: 200, random: randomLcg(1) });

const seed = Object.fromEntries(
  a.layers.flat().map((n, i) => [n.key, i]));

const b = sankeyOrderNodes(
  sankeyAddDummies(sankeyLayers({ links: y2024 })),
  { nsteps: 40, initialOrdering: seed });

The layout pipeline

StageFunctionPurpose
1. LayeringsankeyLayersAssign nodes to layers
2. Dummy nodessankeyAddDummiesRoute multi-layer links through intermediate nodes
3. OrderingsankeyOrderNodesCombinatorial optimisation: median or barycentre sweep, refined by simulated-annealing swaps
4. GeometrysankeyGeometricLayoutGeometric optimisation: coordinates settled by a 1D spring relaxation
5. Render layoutsankeyRenderLayoutResolve node boxes and path geometry
6a. ScenebuildSceneResolve shapes and positions — geometry only
6b. PaintpaintSceneApply colours, fonts and opacities
6c. OutputsceneToSVG / sceneToPDF / sceneToDOMMarkup, vector PDF, or live elements

Every stage but the DOM backend runs headless under Node.js. Rendering is split so that geometry, style and output medium are independent: a diagram can be restyled without being laid out again, measured without being styled at all, and emitted as a string, a PDF, or live interactive elements. In the styling demo a relayout costs about 100 ms and a repaint under 1 ms.

Reproducibility

The ordering stage is randomised. It defaults to Math.random, which means two runs on the same input can disagree. Pass random: randomLcg(seed) to make a run repeatable — required for any measurement you intend to publish. The dataset generator is fully deterministic given its specification and options, so the whole benchmark regenerates identically from a manifest.

The package also includes a measurement module reporting link crossings, total path length, and ribbon overlap, each defined precisely enough to reimplement and validated against shapes whose answers are known analytically. Because it accepts SVG path data, it can measure diagrams produced by any library.

Development

npm run check       # typecheck, then tests
npm test            # tests only
npm run typecheck   # type checking only
npm run types       # emit .d.ts files
npm run demos       # serve the interactive demos
npm run bench:all   # regenerate datasets, run the comparison, draw charts

The source is plain JavaScript annotated with JSDoc, type-checked by TypeScript via checkJs. There is no build step: src/ is what ships. Running npm run types generates .d.ts files so TypeScript consumers get full type information.

Provenance

This package is a port of six Observable notebooks, indexed at Enhanced Sankey Diagram Layouts. The port is not a straight transcription: where the notebooks contained defects that affected published results, they are fixed and the change is documented at the site of the fix. See CHANGELOG.md.
